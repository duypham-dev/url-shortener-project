Security findings
6 findings
Critical
Unbounded Redis key growth — unique_clicks:* has no TTL
sadd is called on every redirect to track unique IPs per shortCode, but no EXPIRE is ever set on these sets. In production, every unique IP for every link accumulates forever. This will silently exhaust Redis memory.
redirecLink.controller.ts
Critical
Rate-limit race condition (INCR + EXPIRE not atomic)
Two concurrent requests see currentCount === 1 simultaneously and both call redis.expire(). This is safe for the TTL but the real issue is the non-atomic check-then-set pattern. Use SET key 0 EX 60 NX then INCR, or Lua script, to make this atomic. Current code also has a bug: the incr/expire block doesn't return after the 429 — next() could still be called.
redirecLink.controller.ts
High
Helmet is commented out — no security headers
The helmet() middleware call is commented out entirely. This means no Content-Security-Policy, no X-Frame-Options, no X-Content-Type-Options headers are sent. XSS and clickjacking mitigations are absent.
app/index.ts L23-27
High
No brute-force or rate-limit protection on auth endpoints
The getLinkRateLimit middleware exists but is only applied to the link-listing route. POST /auth/login and /auth/register have no rate limiting. An attacker can enumerate passwords indefinitely.
auth.route.ts, ratelimit.middleware.ts
Medium
accessToken stored in localStorage — XSS exposure
Any XSS vulnerability (third-party script, Markdown injection) can exfiltrate access tokens. The refreshToken in httpOnly cookie is correctly protected. Consider moving access token to memory only, relying on the refresh cookie for silent renewal.
axiosClient.ts, useAuthStore.ts
Medium
URL validation is bypassable with some redirect URLs
The URL regex /^https?:\/\/.{1,2048}$/ combined with new URL() is generally fine, but doesn't block javascript: URLs in some edge cases, and doesn't prevent SSRF to internal hosts (e.g. http://localhost:6379 would pass). Add an allowlist/denylist for private IP ranges.
generateLink.controller.ts
Backend / architecture findings
5 findings
High
syncExpiredSubscriptions fires on every plan read
getActivePlanContext() is called on every protected route — link creation, analytics, quota check — and it begins with an UPDATE query to expire active subscriptions. This is a write inside a read on a hot path. Move subscription expiry to a scheduled job (cron) or lazy-expire only when a subscription is directly accessed.
subscriptionAccess.service.ts:L115
High
Analytics endpoint runs 6+ sequential/parallel DB queries
getLinkAnalytics controller fires: isLinkOwnedByUser, getActivePlanContext (itself 2 queries), then Promise.all([getDailyClickAnalytics, getReferrerAnalytics, getBreakdownAnalytics]). getBreakdownAnalytics internally runs 4 more rawQuery calls. Total: ~8 round-trips. Consolidate device/browser/os/country into a single CTE query. Cache results with a short TTL (60–300s) per shortCode.
analytics.controller.ts, analytics.service.ts
High
Extra DB lookup on every redirect (hot path)
publishClickEvent calls getUrlOwnerContext() — a findUnique query — on every redirect to get userId for the Kafka message. The redirect path should be as fast as possible. The userId could be embedded in the Redis cache value or fetched in a batched background worker. Every ms counts here.
link.service.ts:L143, redirecLink.controller.ts
Medium
getUserLinks has no pagination — full table scan for power users
findMany with no take/skip limit will return ALL links for a user. A user with 5000 links gets all 5000 serialized on every dashboard load. Add cursor-based or offset pagination.
link.service.ts:getUserLinks
Medium
getActiveSubscriptionPlans never cached
The Upgrade page fetches subscription plans on every mount with no caching. Plans change rarely. Even a simple 5-minute in-memory cache or a Zustand store fetch-once pattern would eliminate repeated identical queries.
Upgrade.tsx, subscription.service.ts
Frontend / state management findings
5 findings
High
Module-level mutable cache bypasses React lifecycle
linksCache, inFlightRequest (useLinks.ts) and linkInfoCache, analyticsCache (useLinkAnalyticsData.ts) are module-level variables. They survive component unmount, hot reloads, and logout. After logout + re-login as a different user, stale data from the previous session can be served. Use React Query or SWR, or at minimum scope cache to an auth context with a cleanup on logout that calls invalidateLinksCache().
useLinks.ts, useLinkAnalyticsData.ts
High
CreateLink form onSubmit only console.logs — feature is a stub
The Create Link page renders a full form UI (destination URL, domain, QR toggle, expiration toggle) but the submit handler just logs to console. createShortenUrl is never called from this page. The /dashboard/links/create route is linked from the Links page header button.
CreateLink.tsx:L63-69
Medium
axiosClient type contract is broken — all callers have wrong types
The response interceptor returns response.data directly, but TypeScript's declared return type is still AxiosResponse. Callers cast with as ApiEnvelope to paper over this. If the interceptor is changed, every cast silently breaks. Extend the axios type definition or use a typed wrapper function.
axiosClient.ts, all api/*.api.ts files
Medium
usePlanStore.fetchPlan has a non-atomic isLoaded check
The guard checks isLoaded && !force then isLoading separately. Two simultaneous callers (DashboardLayout mounts while another component also calls fetchPlan) can both pass the isLoaded check before isLoading is set to true, resulting in duplicate API calls. Use a single pending promise ref as a mutex instead.
usePlanStore.ts:fetchPlan
Medium
getShortUrlDisplay uses API base URL for the short link display
The utility reads VITE_API_BASE_URL (e.g. http://localhost:3000/api/v1) as the short link domain, producing http://localhost:3000/api/v1/abc123. The correct value is VITE_SHORT_LINK_BASE_URL (e.g. https://short.ly). This means every displayed and copied short URL is wrong in environments where these differ.
utils/url.ts

High
QR_COLORS array defined in two separate files
The same 8-colour array is defined identically in CreateLink.tsx and QRPanel.tsx. Extract to a shared constants file (e.g. src/config/qr.constants.ts). Any future change requires editing both files and it's easy to let them drift.
CreateLink.tsx:L7, QRPanel.tsx:L10
Medium
formatTooltipClicks duplicated across two chart components
Identical function bodies in DailyClicksChartCard.tsx and ReferrerPieCard.tsx. Move to a shared chart utilities file.
DailyClicksChartCard.tsx:L18, ReferrerPieCard.tsx:L15
Medium
generateShortLink returns full URL; controllers extract last path segment
The service returns https://short.ly/abc123 and controllers do .split('/').pop() to recover the code. This is fragile — a trailing slash or URL encoding breaks it. The service should return {shortCode, shortUrl} or just the code, letting callers assemble the full URL.
generateLink.service.ts, generateLink.controller.ts
Medium
Inconsistent error handling patterns across controllers
Auth controllers use next(error) for the global handler. Several other controllers (getLinks, getLinkInfo, generateLink) mix inline res.status() responses for some errors and next(error) for others. This means the global error handler's Prisma error mapping is bypassed in some paths.
getLinks.controller.ts, getLinkInfo.controller.ts
Low
